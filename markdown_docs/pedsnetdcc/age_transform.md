## ClassDef AgeTransform
**AgeTransform**: The function of AgeTransform is to add age‑in‑months columns to selected datetime columns of CDM tables and to create corresponding indexes.

**attributes**  
· **columns_by_table** – dictionary mapping CDM table names to a tuple of datetime column names that should receive an age‑in‑months column. The default mapping includes tables such as `condition_occurrence`, `death`, `drug_exposure`, etc. Users may replace this dictionary before invoking the transformation.  
· **ignore_index_by_table** – dictionary that lists, for a given table, age columns for which no index should be created. Currently only the `measurement` table is defined, ignoring `measurement_result_age_in_months`.  
· **AGE_COLUMN_TYPE** – string constant set to `'float'`; indicates the SQL type used for the generated age columns.

**Code Description**  

`AgeTransform` inherits from the abstract base class **Transform**, therefore it must implement the abstract methods `modify_select` and `modify_table`. The class provides a small helper `is_age_column` and overrides `pre_transform` to install required PL/pgSQL functions.

*Class methods*  

1. **is_age_column(cls, column_name, table_name)** – Returns `True` when the supplied `table_name` exists in `columns_by_table` and the `column_name` is listed for that table. Used by callers that need to test whether a column will be transformed.

2. **pre_transform(cls, conn_str, metadata, id_name='dcc', id_type='BigInteger')** – Opens a PostgreSQL connection using `psycopg2`, iterates over the SQL statements contained in the module‑level list `AGE_FUNCTIONS_SQL`, and executes each statement. These statements define the database function `months_in_interval` (and possibly others) that compute the age in months between two timestamps. The `metadata` argument is accepted for API compatibility but is not used.

3. **modify_select(cls, metadata, table_name, select, join, id_name='dcc', id_type='BigInteger')** – Core of the transformation.  
   - If `table_name` is not present in `columns_by_table`, the method returns the original `select` and `join` unchanged.  
   - Retrieves the `person` table from the supplied `metadata`.  
   - Determines the appropriate SQLAlchemy type for the site identifier (`site_id_type`) based on `id_type`.  
   - For each datetime column listed for the table:  
     * Validates that the column exists in the table definition and that the table contains a `person_id` column; raises `ValueError` otherwise.  
     * Constructs a new column name by replacing the suffix `_datetime` with `_age_in_months`.  
     * Builds a SQL expression `months_in_interval(person.birth_datetime, <table>.<datetime_column>)` and labels it with the new column name.  
     * Ensures the `person` table is joined exactly once to the target table (tracked by `joined_already_for_table_name`). The join condition is `person.person_id = <table>.person_id`.  
     * Adds the new column expression to the `select` object via `select.column(new_col)`.  
   - Returns the augmented `(select, join)` pair.

4. **modify_table(cls, metadata, table, id_type='BigInteger')** – Alters the in‑memory SQLAlchemy `MetaData` to reflect the columns added by `modify_select`.  
   - If the table name is not in `columns_by_table`, the method exits without changes.  
   - For each datetime column configured for the table:  
     * Retrieves the existing column object, builds the new column name, and creates a new `Column` instance of type `DOUBLE_PRECISION` (a PostgreSQL `float8`).  
     * Appends the new column to the table definition (`table.append_column(new_col)`).  
     * Unless the column name appears in `ignore_index_by_table` for that table, creates an `Index` object using `Transform.make_index_name` and attaches it to the table.  

*Interaction with other components*  

- **Transform (abstract base class)** – Provides the contract for `pre_transform`, `modify_select`, and `modify_table`. `AgeTransform` fulfills this contract and also uses the static helper `Transform.make_index_name` to generate Oracle‑compatible index identifiers.  
- **transform_runner._transform_age_select_sql** – Calls `AgeTransform.modify_select` for each target table, builds a `SELECT` statement, and wraps it in a `CREATE UNLOGGED TABLE … AS …` command. The resulting SQL is executed later by `_transform_age`.  
- **transform_runner._transform_age** – Executes `AgeTransform.pre_transform` to install the PL/pgSQL functions, then iterates over the SQL statements generated by `_transform_age_select_sql` and runs them in parallel.  
- **tests/age_transform_test.py** – Unit tests verify three aspects: (a) `modify_select` correctly adds age columns and the required join to `person`; (b) tables not listed in `columns_by_table` are left unchanged; (c) `modify_table` creates the expected indexes with deterministic names; (d) `pre_transform` runs without error when a real database connection is supplied. The test suite temporarily overrides `AgeTransform.columns_by_table` to a custom mapping for isolated testing.  

**Note**  
- The transformation only applies to columns whose names end with `_datetime` and are explicitly listed in `columns_by_table`. Columns not listed are ignored.  
- The `person` table must exist in the supplied `metadata` and contain both `person_id` and `birth_datetime` (or `time_of_birth` in test fixtures) columns; otherwise `modify_select` raises a `ValueError`.  
- Index creation is skipped for any column listed in `ignore_index_by_table` to avoid unnecessary indexes on derived columns that are not frequently queried.  
- The generated age columns are of type `float` (PostgreSQL `DOUBLE PRECISION`). If a different numeric precision is required, the class would need to be adapted.  
- The `pre_transform` method expects the global variable `AGE_FUNCTIONS_SQL` to be defined elsewhere in the package; missing definitions will cause a runtime error.  

**Output Example**  

When `AgeTransform.modify_select` processes a table `measurement` that contains the columns `measurement_datetime` and `measurement_result_datetime`, the returned objects produce SQL similar to:

```
SELECT measurement.*,
       months_in_interval(person.birth_datetime, measurement.measurement_datetime) AS measurement_age_in_months,
       months_in_interval(person.birth_datetime, measurement.measurement_result_datetime) AS measurement_result_age_in_months
FROM measurement
JOIN person ON person.person_id = measurement.person_id
```

Correspondingly, after `modify_table` runs, the `measurement` table definition in the SQLAlchemy `MetaData` will contain two new columns (`measurement_age_in_months`, `measurement_result_age_in_months`) of type `DOUBLE PRECISION` and an index on `measurement_age_in_months` (the `measurement_result_age_in_months` index is omitted because it appears in `ignore_index_by_table`).
### FunctionDef is_age_column(cls, column_name, table_name)
**is_age_column**: The function of is_age_column is to determine whether a given column name is recognized as an age‑related column for a specified table.  

**parameters**:  
· column_name: the name of the column to be checked (string).  
· table_name: the name of the table in which the column is expected to exist (string).  

**Code Description**:  
The method accesses the class‑level attribute `columns_by_table`, which is expected to be a dictionary where each key is a table name and each value is a collection (e.g., list, set, or tuple) of column names associated with that table.  
1. It first checks whether `table_name` is present as a key in `cls.columns_by_table`.  
2. If the table exists, it then checks whether `column_name` is contained in the collection mapped to that table.  
3. The expression uses the logical AND operator; both conditions must be true for the method to return `True`.  
4. If either the table is absent or the column is not listed for that table, the method returns `False`.  

**Note**:  
- The method assumes that `cls.columns_by_table` is already populated before calling `is_age_column`.  
- The collection of column names for each table should support the `in` membership test (e.g., list, set, tuple).  
- This method does not validate the types of the inputs; passing non‑string values may raise unexpected errors depending on the underlying collection implementation.  

**Output Example**:  
If `cls.columns_by_table = {'patient': ['age', 'birth_date'], 'visit': ['visit_date']}` then:  

```python
AgeTransform.is_age_column('age', 'patient')   # returns True
AgeTransform.is_age_column('weight', 'patient')   # returns False
AgeTransform.is_age_column('age', 'visit')   # returns False
```

### FunctionDef pre_transform(cls, conn_str, metadata, id_name, id_type)
**pre_transform**: The function of pre_transform is to create the PL/SQL functions required for the age transformation in the target database.

**parameters**: The parameters of this Function.  
· **conn_str**: PostgreSQL connection string used to open a database session.  
· **metadata**: Metadata object required by the abstract Transform interface; it is not used inside this method.  
· **id_name** (optional, default `'dcc'`): Name of the identifier set; retained for signature compatibility.  
· **id_type** (optional, default `'BigInteger'`): Data type of the identifier set; retained for signature compatibility.

**Code Description**:  
The method opens a PostgreSQL connection using the supplied `conn_str` via `psycopg2.connect`. Within the connection context, it creates a cursor and iterates over the iterable `AGE_FUNCTIONS_SQL`, executing each SQL statement with `cursor.execute(stmt)`. The statements in `AGE_FUNCTIONS_SQL` contain the definitions of PL/SQL functions that the age transformation later relies on (e.g., functions to calculate age from birth dates). After all statements have been executed, the cursor and connection contexts are exited, automatically committing the transaction. An explicit `conn.close()` follows the `with` block, ensuring the connection is closed even if the context manager has already done so. The method does not return a value; any SQL execution error propagates as a `psycopg2.ProgrammingError`, which callers handle.

**Relationship with Callers**:  
- **AgeTransform.pre_transform** is invoked by several high‑level transformation runners (`_transform_age`, `_transform_concept`, `_transform_site`, `_transform`, `_transform_target`, `_transform_id`, `_transform_index`). Each runner calls `pre_transform` before generating and executing the main transformation SQL, guaranteeing that the required PL/SQL functions exist in the database.  
- **Test suites** (`AgeTest.test_pre_transform` and `IDMappingTransformTest.test_pre_transform`) call this method to verify that the PL/SQL functions can be created without error in a test database.  
- In generic transformation loops (`_transform` and `_transform_target`), the method is called for every transform class in `TRANSFORMS`, ensuring a uniform pre‑setup step across all transforms.

**Note**:  
- The `metadata`, `id_name`, and `id_type` arguments are kept only for interface compatibility; they have no effect on the execution of this method.  
- The function assumes that `AGE_FUNCTIONS_SQL` is defined elsewhere in the module and contains valid SQL for creating the needed PL/SQL functions.  
- Errors raised during execution (e.g., syntax errors in the SQL statements) will surface as `psycopg2.ProgrammingError`; callers should be prepared to handle this exception.  
- The explicit `conn.close()` after the `with` block is redundant because the context manager already closes the connection, but it does not cause harm.  
- Ensure that the connection string includes the appropriate `search_path` so that the created functions are placed in the intended schema.

### FunctionDef modify_select(cls, metadata, table_name, select, join, id_name, id_type)
**modify_select**: The function of **modify_select** is to augment a SQLAlchemy SELECT statement with derived “age in months” columns for designated datetime columns and to ensure the necessary join to the `person` table.

**parameters**:  
· **cls** – the AgeTransform class (or subclass) invoking the method; provides access to the class‑level mapping `columns_by_table`.  
· **metadata** – a SQLAlchemy `MetaData` object containing the full database schema, including the `person` table.  
· **table_name** – string name of the table currently being processed.  
· **select** – a SQLAlchemy `Select` object that initially selects all columns from `table_name`.  
· **join** – a SQLAlchemy `FromClause` (typically the table itself) that will be extended with additional joins as needed.  
· **id_name** (optional, default `'dcc'`) – name of the site‑specific identifier column; currently only influences the type handling for site IDs.  
· **id_type** (optional, default `'BigInteger'`) – data type of the site identifier (`'BigInteger'` or `'String'`); determines the SQLAlchemy type used for the site ID column (not directly used in the age logic).

**Code Description**:  
1. **Early exit** – If `table_name` is not present in `cls.columns_by_table` (the mapping of tables to datetime columns that should be transformed), the function returns the original `select` and `join` unchanged. This prevents unnecessary processing for tables that have no age‑related columns.  

2. **Prepare the `person` table reference** – Retrieves the `person` table from `metadata.tables`. The function also determines the SQLAlchemy type for a site identifier (`site_id_type`), switching between `BigInteger` and `String(256)` based on `id_type`. Although this type is not used later in the method, it mirrors the pattern used by other transforms.  

3. **Track joins** – A dictionary `joined_already_for_table_name` records whether the `person` table has already been joined for the current `table_name`. This avoids adding duplicate joins when multiple columns in the same table require age calculation.  

4. **Iterate over target columns** – For each column name listed in `cls.columns_by_table[table_name]`:  
   - **Validation** – Confirms that the table exists in the metadata and that the column actually exists; raises `ValueError` if either check fails.  
   - **Person‑ID requirement** – Ensures the table contains a `person_id` column; otherwise a `ValueError` is raised because the age calculation depends on linking to `person`.  
   - **Create derived column** – Constructs a new column expression using the PostgreSQL helper function `months_in_interval`. The expression is:  
     `months_in_interval(person.birth_datetime, <table>.<datetime_column>)`  
     The resulting column is labeled `<original_column_name>` with `_datetime` replaced by `_age_in_months`. For example, `foo_start_time` becomes `foo_start_age_in_months`.  
   - **Add join if needed** – If the `person` table has not yet been joined for this `table_name`, the method adds an inner join:  
     `JOIN person ON person.person_id = <table>.person_id`  
     and records that the join has been performed.  
   - **Append the new column** – The derived column is added to the SELECT clause via `select = select.column(new_col)`.  

5. **Return** – After processing all applicable columns, the function returns the possibly‑augmented `select` object and the (potentially) updated `join` clause.

**Relationship with Callers**:  
- **transform_runner._transform_age_select_sql** – Calls `AgeTransform.modify_select` for each table listed in the target set. The returned SELECT and join objects are compiled into a CREATE TABLE … AS SELECT statement that materializes the transformed table with age columns.  
- **AgeTransform tests** – `AgeTest.test_modify_select` verifies that for a table (`table1`) containing columns listed in `AgeTransform.columns_by_table`, the function adds the correct age columns and the appropriate join to `person`. `AgeTest.test_modify_select_negative` confirms that when a table (`table2`) has no entries in `columns_by_table`, the original SELECT is left untouched.  

Other transforms (ConceptNameTransform, IDMappingTransform, SiteNameTransform, AddIndexTransform) follow the same pattern of receiving a SELECT and join, mutating them, and returning the pair; `modify_select` fits into this pipeline as the age‑specific step.

**Note**:  
- The function assumes the existence of a PostgreSQL function `months_in_interval(person_birth, event_time)`; this function must be defined in the database for the generated SQL to execute.  
- The `id_name` and `id_type` parameters are currently only used to decide the SQLAlchemy type for a site identifier; they do not affect the age calculation. Future extensions may incorporate them.  
- Duplicate joins are prevented per table, but if the same table appears in multiple transform passes (e.g., other transforms also need a join to `person`), each transform maintains its own `joined_already_for_table_name` dictionary, so redundant joins could still be added by different transforms.  

**Output Example**:  
Given a table `table1` with columns `foo_start_time` and `bar_start_time` (both listed for age transformation) and a `person_id` column, the function returns a SELECT that, when compiled, produces SQL similar to:

```
SELECT table1.foo_start_time,
       table1.bar_start_time,
       table1.person_id,
       months_in_interval(person.birth_datetime, table1.foo_start_time) AS foo_start_age_in_months,
       months_in_interval(person.birth_datetime, table1.bar_start_time) AS bar_start_age_in_months
FROM table1
JOIN person ON person.person_id = table1.person_id
```

If the table has no columns slated for age conversion, the returned SELECT and join are unchanged, yielding a simple `SELECT * FROM table2` (or whatever columns were originally selected).

### FunctionDef modify_table(cls, metadata, table, id_type)
**modify_table**: The function of modify_table is to add age‑in‑months columns derived from existing *_datetime* columns to a table’s metadata and to create indexes on those new columns, respecting any ignore‑index rules defined by the class.

**parameters**  
· cls: the AgeTransform class (used to access class‑level configuration such as `columns_by_table` and `ignore_index_by_table`).  
· metadata: a SQLAlchemy `MetaData` instance that contains the full schema definition; it is not modified directly by this method but is required by the Transform interface.  
· table: a SQLAlchemy `Table` object representing the concrete table being processed.  
· id_type: a string indicating the SQLAlchemy type of the site identifier column (default `'BigInteger'`). This parameter is part of the Transform signature but is not used inside the method.

**Code Description**  
1. The method first checks whether the current table’s name appears in the class‑level dictionary `columns_by_table`. This dictionary maps table names to a list of column names that contain a `_datetime` suffix and therefore need an accompanying age‑in‑months column. If the table is not listed, the method returns immediately, leaving the table unchanged.  
2. For each column name listed for the table, the method retrieves the corresponding `Column` object from `table.columns`.  
3. It constructs the name for the new column by replacing the `_datetime` suffix with `_age_in_months`.  
4. A new `Column` instance is created with that name and the SQLAlchemy type `DOUBLE_PRECISION` (a floating‑point type suitable for representing fractional months).  
5. The new column is appended to the table definition via `table.append_column(new_col)`. This updates the in‑memory metadata so that later DDL generation will include the column.  
6. The method then decides whether to create an index for the new column:  
   – If the table name exists in the class‑level dictionary `ignore_index_by_table` **and** the new column name is listed for that table, the index creation step is skipped (`continue`).  
   – Otherwise, an `Index` object is instantiated. The index name is generated by calling `Transform.make_index_name(table.name, new_col_name)`, which produces an Oracle‑compatible, deterministic identifier. The `Index` is associated with the newly added column.  
7. No explicit return statement is present; the function returns `None`. The side‑effects (column addition and index creation) are applied directly to the `table` object passed in.

**Note**  
- The method relies on class attributes `columns_by_table` and `ignore_index_by_table` being correctly populated by the AgeTransform subclass; if they are missing or malformed, the function will either do nothing or raise a `KeyError`.  
- The created index objects are not automatically emitted to the database; they become part of the SQLAlchemy metadata and will be rendered when the pipeline generates DDL statements.  
- The `id_type` argument is part of the abstract `Transform.modify_table` signature but is not used here; it is kept for compatibility with other Transform subclasses.  
- The function assumes that the original column name contains the exact substring `_datetime`; if a column does not follow this naming convention, the replacement will produce an unexpected name.

**Output Example**  
When processing a table named `measurement` that has a column `measurement_datetime`, after calling `AgeTransform.modify_table(metadata, measurement_table)`, the `measurement_table` metadata will contain a new column `measurement_age_in_months` of type `DOUBLE_PRECISION` and an associated `Index` object with a name similar to `mea_mi_ae1fd5b22b92397ca9_ix`. The function itself returns `None`.
