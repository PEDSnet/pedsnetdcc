## ClassDef SiteNameTransform
**SiteNameTransform**: The function of SiteNameTransform is to add a literal site‑name column to every transformed CDM table and to create an index on that column, except for tables listed in the ignore list.

**attributes**  
· ignore_index_by_table: a dictionary that maps table names to a tuple of column names for which an index should **not** be created. The current entries are  
    'fact_relationship': ('site',)  
    'measurement_organism': ('site',)  
    'visit_payer': ('site',)

**Code Description**  

SiteNameTransform is a concrete subclass of the abstract **Transform** class. It implements the two abstract class methods required by the Transform contract: **modify_select** and **modify_table**.

*modify_select*  
- Signature: `modify_select(cls, metadata, table_name, select, join, id_name='dcc', id_type='BigInteger')`  
- Purpose: inject a new column named **site** into the SELECT clause of the table being processed.  
- Implementation steps:  
  1. Verify that the `metadata.info` dictionary contains a key `'site'`. If the key is missing, a critical log entry is emitted and a `RuntimeError` is raised.  
  2. Build a literal SQL expression containing the site name, cast to `varchar(32)`. The expression is created with `literal_column("'{0}'::varchar(32)".format(metadata.info['site']))` and labelled as `'site'`.  
  3. Append the new column to the incoming `select` object via `select.column(new_col)`.  
  4. Return the modified `select` together with the unchanged `join` object. No additional joins are required for this transformation.

*modify_table*  
- Signature: `modify_table(cls, metadata, table, id_type='BigInteger')`  
- Purpose: update the in‑memory SQLAlchemy `Table` definition to reflect the new **site** column and, when appropriate, create an index on that column.  
- Implementation steps:  
  1. Create a new `Column` instance: `Column('site', String)`.  
  2. Append the column to the supplied `table` with `table.append_column(new_col)`.  
  3. If the table name appears in `ignore_index_by_table`, the method returns immediately, leaving index creation to the caller.  
  4. Otherwise, an `Index` object is instantiated using the helper `Transform.make_index_name(table.name, 'site')` to generate an Oracle‑compatible index name, and the index is associated with the new column. The index object is not explicitly added to the table’s index collection because SQLAlchemy automatically registers it when the `Index` is constructed with the column.

*Interaction with the Transform framework*  
- `SiteNameTransform.modify_select` is invoked for each target table inside `pedsnetdcc/transform_runner.py/_transform_site_select_sql`. The runner builds a basic `select([table])` and passes it, together with the table’s join object, to this method. The returned SELECT is then compiled into a `CREATE UNLOGGED TABLE … AS SELECT …` statement that materialises the transformed table.  
- After all SELECT statements have been generated, `SiteNameTransform.modify_metadata` (inherited from **Transform**) iterates over every non‑vocabulary table in the metadata and calls `SiteNameTransform.modify_table`. This ensures that the metadata used later for DDL generation contains the new **site** column and the appropriate index.  
- Unit tests in `pedsnetdcc/tests/site_name_transform_test.py` verify both behaviours: `test_modify_select` checks that the generated SELECT includes the literal `'test'::varchar(32) AS site`; `test_modify_metadata` confirms that an index is created for a regular table and that vocabulary tables (e.g., `concept`) remain unchanged.

**Note**  
- The literal site value is taken directly from `metadata.info['site']`; callers must populate this entry before invoking the transformation (the runner does this).  
- Tables listed in `ignore_index_by_table` receive the **site** column but deliberately skip index creation to avoid unnecessary indexes on relationship or lookup tables.  
- The index name is generated by `Transform.make_index_name`, which guarantees compliance with Oracle’s 30‑character limit and reduces the risk of name collisions.  
- Because the transformation only adds a column, it never modifies existing columns or joins; therefore it is safe to apply after other transformations that may depend on the original join structure.

**Output Example**  

*SELECT clause after modify_select (for a table named `table1` with columns `foo` and `bar` and site value `'test'`)*  

```
SELECT table1.foo,
       table1.bar,
       'test'::varchar(32) AS site
FROM table1
```

*Index creation DDL generated by modify_table (for a table named `table1` that is not in the ignore list)*  

```
CREATE INDEX tab_s_e8e4cc181f175c06e6d80_ix
  ON table1 (site)
```
### FunctionDef modify_select(cls, metadata, table_name, select, join, id_name, id_type)
**modify_select**: The function of modify_select is to add a constant site name column to a SQLAlchemy select statement for a given table.

**parameters**:  
· cls: the class on which the method is called (SiteNameTransform).  
· metadata: SQLAlchemy MetaData object containing table definitions and an `info` dictionary.  
· table_name: string name of the table being transformed (unused inside the method but required by the transform interface).  
· select: a SQLAlchemy `Select` object representing the current SELECT clause.  
· join: a SQLAlchemy table or join object representing the FROM/JOIN clause (returned unchanged).  
· id_name: optional identifier name for the site id set (default `'dcc'`; not used in this transform).  
· id_type: optional SQLAlchemy type for the site id set (default `'BigInteger'`; not used in this transform).

**Code Description**:  
1. The method first checks that the `metadata.info` dictionary contains a key `'site'`. If the key is missing, it logs a critical message and raises a `RuntimeError`. This ensures that the site name is available before proceeding.  
2. It creates a new SQLAlchemy column expression using `literal_column`. The literal is the site name taken from `metadata.info['site']`, formatted as a PostgreSQL‑compatible literal of type `varchar(32)`. The expression looks like `'<site>'::varchar(32)`.  
3. The literal column is labeled `'site'` so that the resulting column name in the SELECT list will be `site`.  
4. The new column expression is added to the existing SELECT clause by calling `select.column(new_col)`. This returns a new `Select` object that includes all previously selected columns plus the constant site column.  
5. The method returns a tuple `(select, join)`. The `select` object now contains the additional site column, while the `join` object is passed through unchanged because this transform does not modify the FROM/JOIN part of the query.

**Relationship with Callers**:  
- `SiteNameTransform.modify_select` is part of the `TRANSFORMS` pipeline used by several helper functions in `transform_runner.py` (`_transform_select_sql`, `_transform_site_select_sql`, etc.). Each of these functions iterates over all tables in the source schema, builds an initial `select` and `join` for each table, and then applies every transform in `TRANSFORMS` sequentially. `SiteNameTransform.modify_select` contributes the site column to every table’s SELECT clause during this pipeline.  
- Unit tests in `pedsnetdcc/tests/site_name_transform_test.py` verify that after the method is applied, the generated SQL contains the literal site value (`'test'::varchar(32) AS site`) alongside the original table columns.  
- Other transforms (e.g., `AgeTransform`, `ConceptNameTransform`, `IDMappingTransform`) follow the same signature but perform different modifications. The consistent interface allows `SiteNameTransform.modify_select` to be interchangeable within the transformation chain.

**Note**:  
- The method does not alter the join structure; it only appends a column to the SELECT list.  
- The `id_name` and `id_type` parameters are present to satisfy the common transform interface but are ignored in this implementation.  
- The site name must be set in `metadata.info['site']` before invoking the transformation; otherwise a `RuntimeError` will be raised.  
- The literal column is cast to `varchar(32)`, matching the expected type for the `site` column in the target schema.

**Output Example**:  
If `metadata.info['site']` is `'test'` and the original select is `SELECT table1.foo, table1.bar FROM table1`, after calling `modify_select` the returned select object will compile to:

```
SELECT table1.foo, table1.bar, 'test'::varchar(32) AS site
FROM table1
```

### FunctionDef modify_table(cls, metadata, table, id_type)
**modify_table**: The function of **modify_table** is to add a literal `site` column to a table’s SQLAlchemy metadata and optionally create an index on that column.

**parameters**:  
· **cls** – the concrete transformation class (`SiteNameTransform`). It provides class‑level configuration such as `ignore_index_by_table`.  
· **metadata** – a SQLAlchemy `MetaData` instance that contains the full schema definition; it is not directly modified in this method but is required by the abstract signature.  
· **table** – a SQLAlchemy `Table` object representing the CDM table currently being processed.  
· **id_type** – a string indicating the SQLAlchemy type of the site identifier (default `'BigInteger'`). This argument is part of the abstract signature but is not used inside the method.

**Code Description**:  
1. **Create the new column** – `new_col = Column('site', String)` constructs a new column named `site` with a generic `String` type. The column is not yet attached to any table.  
2. **Append the column to the table** – `table.append_column(new_col)` mutates the supplied `Table` object in‑place, adding the `site` column to the in‑memory metadata. This ensures that later DDL generation will include the column when the temporary table is materialised.  
3. **Conditional index creation** – The method checks whether the table’s name appears in the class attribute `ignore_index_by_table`. If the name is present, the method returns immediately, leaving the column without an index.  
4. **Create an index** – When the table is not ignored, `Index(Transform.make_index_name(table.name, 'site'), new_col)` constructs a SQLAlchemy `Index` object.  
   - `Transform.make_index_name` is a static utility defined in the abstract base class `Transform`. It generates an Oracle‑compatible index identifier that respects the 30‑character limit by combining a three‑character table abbreviation, a column abbreviation derived from the column name, and a truncated MD5 hash.  
   - The `Index` object is instantiated but not explicitly attached to the `Table`. In SQLAlchemy, creating an `Index` with a column that belongs to a table automatically registers the index with that table’s metadata. Consequently, when the metadata is later reflected or emitted, the index will be created in the database.  

Overall, the method mutates the metadata for each non‑vocabulary table by adding a `site` column and, unless excluded, an index on that column. The transformation is applied uniformly across all tables processed by the `SiteNameTransform` class.

**Note**:  
- The method relies on the class attribute `ignore_index_by_table`, which must be defined in `SiteNameTransform`. Tables listed there will receive the `site` column but will not have an index created, typically to avoid unnecessary indexes on very large or already‑indexed tables.  
- The `id_type` parameter is unused; it exists only to satisfy the abstract method signature defined in `Transform`.  
- The `Index` object is created without being stored in a variable; SQLAlchemy registers it automatically via the column reference.  
- Because the method modifies the `Table` object in place, callers should not expect a return value; the changes are reflected directly in the supplied `metadata`.  

**Output Example**:  
```python
# Assume `tbl` is a SQLAlchemy Table object for the "measurement" table
SiteNameTransform.modify_table(metadata, tbl)

# After execution:
# tbl.c contains a new column:
#   Column('site', String)

# An index is also present in tbl.indexes, e.g.:
#   Index('mea_s_ae1fd5b22b92397ca9_ix', tbl.c.site)
# (The exact index name depends on Transform.make_index_name and the NAME_LIMIT constant)
```
